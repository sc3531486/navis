# Product

## Register

product

## Users

Navis Go is for developers working inside a desktop AI coding tool. They are reading code, asking an agent to make changes, inspecting tool activity, managing local workspaces, and reviewing edits under time pressure.

## Product Purpose

Navis Go helps developers coordinate AI-assisted coding work from one desktop shell: conversation, tools, workspace files, terminal actions, provider routing, extensions, tasks, and design guidance. Success means the user can understand what the agent is doing, approve risky actions, inspect real facts, and continue work without leaving the app.

## Brand Personality

Quiet, capable, precise. The interface should feel like a serious developer instrument: dense enough for repeated work, calm enough for long sessions, and explicit about state, risk, and provenance.

## Anti-references

Do not make the app feel like a marketing site, a generic SaaS dashboard, or a decorative extension marketplace. Avoid oversized heroes, decorative cards, fake placeholder panels, duplicated navigation systems, and any UI that hides whether data is real or projected.

## Design Principles

- Real surfaces only: visible menus, panels, and commands must execute through a real host path.
- Kernel-aligned product shape: UI can present Registry, Pipeline, Event Bus, Policy, and Audit outcomes, but it must not create parallel back-end systems.
- High-signal density: show current work, status, risk, and provenance without verbose explanation.
- Local trust: destructive or external actions must make scope and authority obvious.
- One shell, many views: new features should enter through existing menus, commands, panels, and settings surfaces.

## Accessibility & Inclusion

Target WCAG AA contrast for primary text and controls. Respect reduced motion. Keep keyboard access, focus states, and readable compact text as first-class requirements because the app is used for long developer sessions.
