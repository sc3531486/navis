## 一、模块概述

### 1.1 定位

i18n 提供多语言支持，管理文案翻译、语言切换、日期/数字格式化。

### 1.2 职责边界

```
负责：
├── 多语言文案管理（JSON 语言包）
├── 语言切换（运行时动态切换）
├── 日期/数字/货币格式化
├── 复数形式处理
├── 插值变量支持
└── 缺失翻译回退

不负责：
├── AI 对话语言（由 Agent/模型决定）
└── 用户生成内容翻译
```

## 四、接口定义

```typescript
// 翻译函数
t(key: string, params?: Record<string, any>): string
t(key: string, count: number): string  // 复数形式

// 语言管理
i18n.getLocale(): string
i18n.setLocale(locale: string): void
i18n.getAvailableLocales(): string[]

// 格式化
i18n.formatDate(date: Date, format?: string): string
i18n.formatNumber(num: number, options?: Intl.NumberFormatOptions): string
i18n.formatRelative(date: Date): string  // 如 "3分钟前"，基于 Intl.RelativeTimeFormat
```

`formatRelative` 内部使用 `Intl.RelativeTimeFormat` API 实现，根据当前 locale 自动输出对应语言的相对时间文本（如中文"3分钟前"、英文"3 minutes ago"）。

## 五、Hotkey description 翻译支持

Hotkey 模块中 `HotkeyBinding` 的 `description` 字段支持 i18n 翻译 key：

- `description` 可以是普通文本（如 `"打开命令面板"`），也可以是 i18n key（如 `"hotkey.open_command_palette"`）
- 前端渲染快捷键列表时，检测 `description` 是否以已知命名空间前缀开头，若是则调用 `t()` 翻译
- 默认快捷键推荐使用 i18n key，扩展注册的快捷键可自由选择

```toml
# 默认快捷键使用 i18n key
[[hotkeys]]
keybinding = "Ctrl+Shift+P"
command = "commandPalette.open"
description = "hotkey.open_command_palette"
scope = "app"
```

## 六、Extension 多语言策略

扩展通过 `contributes.i18n` 声明本地化资源（数据结构见 34-extension-ui-open-architecture §3.1：`i18n = Option<Vec<I18nResource>>`，`I18nResource { lang, entry }`，`entry` 为相对路径，须位于 `ExtensionUI/locales/` 下）。

```json
{
  "id": "com.example.my-extension",
  "contributes": {
    "i18n": [
      { "lang": "zh-CN", "entry": "./ExtensionUI/locales/zh-CN.json" },
      { "lang": "en-US", "entry": "./ExtensionUI/locales/en-US.json" }
    ]
  }
}
```

目录结构（`entry` 相对扩展根，需位于 `ExtensionUI/locales/` 下）：

```
my-extension/
├── extension.json
└── ExtensionUI/locales/
    ├── zh-CN.json
    └── en-US.json
```

宿主在扩展 enable 时校验 `entry` 路径与 JSON 合法性，并将语言包加载到前端 i18n（`ui_list_extension_locales`，见 34-extension-ui-open-architecture §15.1 F-I6）；28 号承接前 `contributes.i18n` 必须加入 reject_unbound!（禁止静默忽略，见 34 号风险 14）。

扩展翻译 key 以扩展 ID 为命名空间前缀，避免冲突：

```json
// my-extension/ExtensionUI/locales/zh-CN.json
{
  "my-extension.hello": "你好",
  "my-extension.config.title": "扩展配置"
}
```

切换语言时，如果扩展没有对应语言的翻译文件，则回退到扩展的默认语言（扩展 `extension.json` 中声明的 `defaultLocale`，默认 `en-US`）。

---

## 七、回退链机制

当翻译 key 在当前语言包中缺失时，按以下回退链查找：

```
zh-CN（当前语言）→ en-US（默认语言）
```

回退过程中，如果最终仍未找到翻译 key，则：

1. 输出 key 本身作为文本（如 `"missing.key"`）
2. 在控制台输出 `missing key` 警告日志，便于开发阶段发现遗漏

## 八、使用示例

```tsx
// 基本翻译
const label = t('common.ok')                    // "确定"
const msg = t('agent.thinking')                  // "思考中..."

// 插值
const msg = t('session.message_count', { count: 42 })  // "共 42 条消息"

// 复数
const msg = t('notification.unread', 5)          // "5 条未读通知"

// Solid.js 组件中使用
function MyComponent() {
  return (
    <div>
      <h1>{t('settings.title')}</h1>
      <button>{t('common.save')}</button>
      <span>{t('agent.thinking')}</span>
    </div>
  )
}
```

## 九、语言切换流程

```
用户在设置页面切换语言
     │
     ▼
i18n.setLocale('en-US')
     │
     ▼
加载对应语言包（懒加载）
     │
     ▼
更新 Solid Store（触发响应式更新）
     │
     ▼
所有使用 t() 的组件自动重新渲染
     │
     ▼
持久化到 Config
```
