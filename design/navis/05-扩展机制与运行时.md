## 一、模块概述与核心设计原则

### 1.1 定位
扩展机制是 Navis 的**核心灵魂**。Navis 遵循 **“万物皆扩展（Everything is an Extension）”** 的设计哲学，所有业务领域（AI 平台、Agent、会话、项目、终端、知识库、银行柜面、双录等）全部作为插件实现。

### 1.2 核心设计原则
1. **统一生命周期（Cordis Extension Lifecycle）**：前端采用 Cordis IoC 容器与响应式上下文（`NavisContext`），后端采用动态 `ExtensionRegistry`。
2. **多语言子进程（Multi-Language Subprocesses）**：重型后端或系统调用以标准子进程（Node.js / Python / Rust / 可执行二进制）运行，通过 stdio JSON-RPC 承接请求。
3. **泛型贡献点分发（Generic Contribution Points）**：宿主 `ContributionRegistry` 不对业务字段设限，支持扩展作为“二级宿主”监听其他插件的扩展点。
4. **无限级插槽嵌套（Slot-in-Slot 递归树）**：扩展既可以挂载到上级插槽，也可以向系统暴露子插槽。

## 二、Cordis 容器与上下文 API

前端插件入口实现 `NavisPlugin` 接口，通过 `apply(ctx: NavisContext)` 编排生命周期与能力注册：

```typescript
export interface NavisPlugin {
  name: string;
  apply: (ctx: NavisContext) => void | Promise<void>;
}
```

### 2.1 上下文 API 五大子系统

1. **`ctx.services`（IoC 依赖注入）**：
   - `ctx.services.provide(name, instance)`：向容器注册单例服务。
   - `ctx.services.use<T>(name)`：消费已注册的服务实例。
2. **`ctx.events`（事件总线与流水线）**：
   - `ctx.events.on(event, handler)`：订阅全局事件。
   - `ctx.events.emit(event, payload)`：广播同步事件。
   - `ctx.events.waterfallHook(event, middleware)`：中间件流水线，支持请求在多个扩展间包装传递。
3. **`ctx.views`（视图插槽投影）**：
   - `ctx.views.register(slotName, contribution)`：向指定插槽注入 UI 组件。
4. **`ctx.commands`（通用命令系统）**：
   - `ctx.commands.register(commandId, handler)`：注册本地命令处理函数。
   - `ctx.commands.execute(commandId, args)`：执行命令（优先本地执行，未匹配则经 IPC 路由到后端）。
5. **`ctx.effect`（副作用清理）**：
   - 绑定的定时器、DOM 监听随插件卸载自动释放。
