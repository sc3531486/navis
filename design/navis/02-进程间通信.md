# 02 — 进程间通信详细设计（IPC Inter-Process Communication）

> 模块编号：02 | 模块归属：Navis 通用宿主底座 / 通信层  
> 依赖：Tauri 2 IPC, Tracing  
> 被依赖：所有扩展、动态路由网关、UI 响应式层

---

## 一、模块概述与定位

### 1.1 定位
IPC 模块负责前端 Webview 与 Rust 后端宿主之间的命令解码、参数校验、状态注入、错误编码和响应返回。
宿主为所有业务扩展提供统一的命令路由，不实现第二套平行总线。

### 1.2 职责边界
```text
负责：
├── Tauri command 注册和参数反序列化（navis_dispatch_rpc / navis_dispatch / core_route_ipc）
├── IPC 错误结构化返回与链路日志追踪
├── 动态 RPC 路由分发（进程内动态路由与插件子进程转发）
└── 调用后端业务服务并返回结果

不负责：
├── 扩展具体业务命令逻辑（由各业务扩展实现）
├── 业务持久化存储（统一接入通用 Storage）
└── 流式长连接推送（由 03-流式数据通道 模块专门承接）
```

## 二、通信接口定义

### 2.1 前端调用方法（`src/core/tauri-bridge.ts`）

```typescript
import { invoke } from '@tauri-apps/api/core';

/** 同步 RPC 调用：路由到指定插件的后端进程 */
export async function coreRouteIpc<T = any>(
  pluginId: string,
  method: string,
  params: Record<string, any> = {},
): Promise<T> {
  return invoke<T>('core_route_ipc', { pluginId, method, params });
}

/** 统一 Action 分发（自动识别进程内路由或子进程） */
export async function navisDispatch<T = any>(
  extension: string,
  action: string,
  data: Record<string, any> = {},
): Promise<T> {
  return invoke<T>('navis_dispatch', { extension, action, data });
}
```

### 2.2 后端 Rust 路由实现（`src-tauri/src/core/ipc_bridge.rs`）

```rust
#[tauri::command]
pub async fn core_route_ipc(
    transport: State<'_, Arc<TransportRouter>>,
    plugin_id: String,
    method: String,
    params: Value,
) -> Result<Value, String> {
    transport.send_rpc(&plugin_id, &method, params).await
}
```
